# Plan: Manual override for the canicule mode

## Goal

Add a manual override switch that forces `binary_sensor.mode_canicule` ON, lasting only for the current day and resetting automatically at night.

## Current behavior

`binary_sensor.mode_canicule` (templates.yaml:451-456) is a pure temperature template:
- ON when outdoor temp ≥ 30°C **or** indoor average temp ≥ 26°C

It is consumed by automations in `automations/global/heatwave.yaml` (close/reopen covers, notifications).

## Chosen behavior (confirmed with user)

- New helper `input_boolean.canicule_forcee` ("Canicule - Forçage manuel").
- `binary_sensor.mode_canicule` = ON if **override is on** OR temperature conditions.
- Override is reset during the night when `binary_sensor.mode_jour` turns off (dusk or 22:00).
  - Consequence: an override set during the night persists into the following day (accepted).

## Changes (3 files)

### 1. `input_booleans.yaml` — add the override helper

Append:

```yaml
canicule_forcee:
  name: "Canicule - Forçage manuel"
  icon: mdi:weather-sunny-alert
```

### 2. `templates.yaml` — fold override into `mode_canicule` (line 454-456)

Change the `state` template of `binary_sensor.mode_canicule` to:

```yaml
      state: >-
        {{- states('input_boolean.canicule_forcee') == 'on'
            or states('sensor.maison_meteo_france_forecast_for_city_wasquehal_nord_pas_de_calais_59_fr_temperature_exterieure') | float(0) >= 30
            or states('sensor.temperature_moyenne_de_la_maison') | float(0) >= 26 -}}
```

### 3. `automations/global/heatwave.yaml` — add nightly reset automation

Append a new automation (matching the existing `Canicule - ...` style of this file):

```yaml
- alias: Canicule - Réinitialisation du forçage manuel
  id: canicule_reset_manual_override
  description: >
    Réinitialise le forçage manuel du mode canicule pendant la nuit,
    lorsque le mode jour se termine, afin que le forçage ne s'applique
    qu'à la journée en cours.
  mode: single
  trigger:
    - platform: state
      entity_id: binary_sensor.mode_jour
      to: "off"
  condition:
    - condition: state
      entity_id: input_boolean.canicule_forcee
      state: "on"
  action:
    - service: input_boolean.turn_off
      target:
        entity_id: input_boolean.canicule_forcee
```

## Notes / edge cases

- No `availability` guard needed on the template: `input_boolean` is always available.
- HA restart during the night: the reset trigger only fires on a `mode_jour` state change, so an override left on overnight across a restart would persist until the next night's reset. Acceptable; no extra handling.
- `binary_sensor.mode_jour` is defined at templates.yaml:457-460; it turns off at `min(next_dusk, 22:00)`.
